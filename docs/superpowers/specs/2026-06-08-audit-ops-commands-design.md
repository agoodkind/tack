# TACK-328: Audit ops commands (design)

## What this does

Make every mutating ops command, plus every read op, write an audit event.
Today the Recorder fires only at the API/MCP boundary
(`internal/adapters/mcp/tools/helpers.go` `recordToolAudit`, plus the auth
middleware). Ops commands emit `slog` only.

So an operator can edit product data (`ops repair apply`), rotate audit
credentials (`ops audit seed-roles`), migrate, provision, or seed prod with no
entry in `audit.events`. That is the SOC2/GDPR/HIPAA/ISO gap the ticket names.

This unblocks TACK-327 (lock prod data-plane access to the ops surface). Locking
access is only safe once ops are audited, otherwise it just relocates the blind
spot. TACK-328 already carries a `blocks` relationship to TACK-327.

## Settled decisions

1. Operator identity comes from a pluggable source, not hard-coded env. Actor
   kind is a new `operator` (code 5).
2. Global ops record on a reserved system-org chain. Entity ops (`repair apply`)
   record on the target node's real org.
3. Steady-state mutations are fail-closed. Bootstrap ops are exempt. Reads
   require an operator but never block on a down ledger.
4. Scope: all mutating ops plus read events for inspect/verify/validate.
5. Wiring: one unified ops registry with a required audit spec, routed through
   one dispatch choke-point.

## Section 1: unified ops registry

One registry replaces the three separate dispatch trees (batch `ops.Run`, the
cobra CLI ops in `cli.go`, and top-level `migrate`/`seed`).

- One `OpDescriptor` per command: `Name`, `Path` (tree placement), `Audit`
  (required), flag/arg declarations reusing `clispec.Registry` and
  `cli.Factory`, and `Run func(ctx, *Env, args) error`.
- One `Register(desc)` whose signature requires `Audit`, so a mutating op cannot
  be wired in without declaring how it audits.
- The cobra tree is generated by walking the registry. This replaces the
  hand-built groups in `cli.go` and the hand-written `backup`/`deploy` subtrees;
  each subcommand (`backup verify`, `deploy push`) becomes its own descriptor.
- `migrate` and `seed` move out of `cmd/server/commands.go` into descriptors.
- Both the cobra path and the batch path call one `Dispatch(ctx, cfg, desc, fn)`
  choke-point, so exactly one place records.
- Specialized ops still build their own Docker/git deps inside `Run`; common
  `Pool`/`Stores` come from `Env`.

## Section 2: operator identity (pluggable)

The "who did it" stamp on an audit event is the actor: a kind plus an id, name,
and email. Existing kinds are `user`, `service`, `system`, `api_token`. Ops
events get a new kind `operator` (code 5) so operator actions are filterable
apart from seed/system actions.

- `internal/ops/operator.go`:
  - `OperatorPrincipal`: id, email, name, source.
  - `OperatorIdentitySource`: one method, `Resolve(ctx)`.
  - `EnvOperatorSource`: one implementation, reads `TACK_OPERATOR_ID` /
    `TACK_OPERATOR_EMAIL` / `TACK_OPERATOR_NAME`. Missing or bad id returns an
    error, which is what makes a steady-state op refuse to run.
- `Dispatch` and commands only call `Resolve`. Nothing in them reads env.
- A later RBAC/OAuth/SSO/IdP source for the internal Tack engineering and
  operations team implements the same one method and is selected at the single
  construction site. This identity layer authenticates the internal team running
  ops, separate from the product's multi-tenant end-user auth
  (`api_tokens`/`org_members`).
- `internal/config/config.go` gains the three `TACK_OPERATOR_*` fields via
  `caarlos0/env`.
- `internal/audit/recorder.go` gains `ActorOperator` and the code-5 entry in the
  actor-to-SMALLINT mapping.

## Section 3: recorder, system-org, preflight

- Extract `buildAuditRecorder` from `cmd/server/audit_runtime.go` into
  `internal/audit` as `NewRecorderFromConfig(cfg)`. `cmd/server` calls it too.
  `Dispatch` calls it to get the same Kafka producer, so the audit-consumer
  stays the only writer of `audit.events` (the cutover invariant holds).
- Add a fixed `SystemOrgID` UUID in `internal/audit` for global-op chains. It is
  only a chain partition key, not a product node in FDB. Verify
  `audit.events.org_id` has no foreign key first.
- Add an optional interface `ReachabilityChecker` with `Ping(ctx)`, implemented
  on the Kafka recorder (metadata request) and the YB recorder (`SELECT 1`);
  Noop returns nil. The core `Recorder` interface and the MCP path stay
  untouched. `Dispatch` pings before a mutating op so it can abort before
  changing anything.

Global op example (`ops audit seed-roles` on live prod):

```
org_id      = SystemOrgID
actor_kind  = 5            (operator)
actor_id    = <operator>
action      = ops.audit.seed_roles
entity_kind = audit_role
outcome     = ok
```

Entity op example (`ops repair apply --node 7a31...`): the descriptor's
`ResolveOrg` callback runs `reader.Resolve(nodeID)`, so the event lands on the
customer's real org with the repair plan as the delta:

```
org_id      = <customer org of 7a31...>
actor_kind  = 5
actor_id    = <operator>
action      = ops.repair.apply
entity_kind = node
entity_id   = 7a31...
delta       = {before: {...}, after: {...}}
outcome     = ok
```

## Section 4: failure handling

| Class | Operator required | Ledger down (Ping fails) | Record fails |
| --- | --- | --- | --- |
| Steady mutation (repair apply, reindex, backfill, seed-roles live, backup, deploy) | Yes, abort if unresolved | Abort before mutating | Exit non-zero, loud Error |
| Bootstrap (provision, first-boot migrate/seed/seed-roles) | No, record if available | Proceed | Best-effort; provision emits terminal `ops.provision` once the stack is up |
| Read (inspect, verify, validate, repair preview) | Yes, abort if unresolved | Proceed | Best-effort |

Honest limit on fail-closed: no transaction spans FoundationDB/Yugabyte and
Kafka, and cross-database transactions are forbidden in this repo. The guarantee
is preflight, then mutate, then record. The `Ping` before the mutation is what
prevents an unrecorded change when the ledger is down. If the record fails in the
small window after a passing ping, the mutation already happened, so the op exits
non-zero and logs loudly for reconciliation. True atomic mutate-plus-record is
not achievable here.

## Section 5: verification

- `make build` (go-makefile baseline-gated pipeline) and `make check`.
- Unit (`make test-unit`, `./internal/ops/...`, `--no-deps`) with a fake
  recorder, identity source, and `ReachabilityChecker`:
  - `EnvOperatorSource`: missing id, bad id, valid id.
  - `Dispatch`: steady mutation aborts on unresolved operator; aborts on Ping
    failure; records on success. Read aborts on unresolved operator; proceeds on
    Ping failure (best-effort). Bootstrap proceeds with no operator and no
    ledger.
  - Registry: every registered mutating op carries a non-empty audit verb.
- Integration (`make test-integration`, single-node FDB + Yugabyte): run a real
  mutating op (reindex or repair apply), assert a row in `audit.events` with
  `actor_kind=5`, the right `action`, the expected `org_id` (SystemOrgID for
  global, the real node org for repair apply), and that `audit.chain_heads`
  advanced for that `(org, shard)`.
- QA manual, never prod and never first: set operator identity, run `repair
  apply` and `audit seed-roles`, query the ledger via the audit MCP tools,
  confirm operator events and chain continuity. Run a mutation with the broker
  down (expect abort). Run an `inspect` with the broker down (expect it proceeds,
  recorded once the ledger returns).

## Files

New: `internal/ops/operator.go`, `internal/ops/audit.go` (`AuditSpec`,
`Dispatch`), the unified registry types.

Changed: `internal/ops/ops.go`, `internal/ops/cli.go`, the
`repair`/`audit`/`inspect`/`verify`/`validate`/`provision`/`reindex`/`backfill`/
`backup`/`deploy` command files, `cmd/server/commands.go`, `cmd/server/seed.go`,

`internal/audit/recorder.go`, `internal/audit/verbs.go`, plus
`NewRecorderFromConfig`, `SystemOrgID`, and `ReachabilityChecker` in
`internal/audit`.

## Risks to confirm

- `tack-ops` is `network_mode: host`; `AUDIT_KAFKA_BROKERS` must resolve to a
  host-reachable broker for the SQL-only ops (migrate, seed-roles), the same
  constraint class that forced seed into the app container (TACK-318). If
  unreachable, decide the broker address in the configs repo / Ansible env, or
  run the affected ops through the app container.
- Confirm `repair apply` runs in the app container, since tack-ops cannot reach
  FDB on host networking.
- Confirm `audit.events.org_id` has no foreign key, so the synthetic system org
  is legal.
