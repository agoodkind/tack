# Search acceptance criteria

Search releases must pass these criteria through public operations with real FoundationDB, OpenSearch, the deployed model, and authentication. Storage expansion must repeat them at larger node sizes. A criterion without observed evidence remains unverified.

## Evidence and environment

- Record the exact Tack and Configs revisions, dirty files, image digests and architecture, model and tokenizer checksums, index settings, shard counts, byte and work bounds, fixture identities, corpus, workload, commands, exit codes, observations, and artifacts. Distinguish provisioning, deployment, public activation, behavior acceptance, capacity, and cleanup.
- Require QA acceptance before production. Local tests, source inspection, private helper calls, mocks, recorded responses, engine traces, and profiles do not establish deployed acceptance. Traces and profiles can support evidence from public operations. Public fixtures must use the real bearer-token lookup and organization membership. Keep raw fixture credentials in memory, store only token hashes, use isolated test data, and clean up identities and data when the fixture ends. Use an ephemeral CA and server certificate for the disposable TLS fixture. Test both JSON and SSE responses with audit recording active.
- Exercise the production official stable client against the pinned OpenSearch 3.8.0 engine. Cover typed creation, settings, split, bulk indexing and partial updates, write blocking, refresh, point-in-time creation and deletion, search construction, alias changes, index and document reads, deletion, metrics, routing, and close. Preserve replacement point-in-time IDs and exact sort JSON. Exercise concrete ML Commons requests through the official execution and error decoder. Prove that OpenSearch rejects `version` and `version_type` on a bulk update. Call the registered provision and verify operations against the real TLS fixture. Vary model, mapping, alias, and topology expectations independently and require a concrete mismatch for each. Reject custom HTTP transport, route selection, connection pools, error decoding, and application retry loops.
- Require complete permanent audit evidence for public search, operator commands, sessions, indexing, model repair, and replacement work. Inspect verified actors, initiating identities, complete targets, original time, committed order, outcomes, field and relationship changes, read manifests, returned counts, selection criteria, and fingerprints. Exercise authorization refusals, admission and finalization failures, partial work, interruptions, and recovery. Withhold results or effects when required recording fails. Require `runtime audit coverage` and applicable integration checks before merge and verify accepted behavior on QA before release.

## Build and lint gates

- Run `make build` on the exact unedited implementation base and after each coding task before commitment. Stop on a base failure. Use the current shared build and lint configuration and fix every new finding within its owning change.
- Connect every new production declaration to a production entry point in the change that adds it. Do not commit future-only interfaces, constructors, helpers, adapters, or exports.
- Accept zero new lint, complexity, strict-analyzer, and dead-code findings. Do not edit baselines or use `accept-new` targets. Use concrete types, injected clocks, contextual logging, returned errors, and recovered goroutines. Do not add `any`, empty interfaces, `panic`, direct `time.Now`, `context.TODO`, unprotected goroutines, or lint suppressions.
- Require a clean final implementation build and all required real-dependency groups. Compilation, successful startup, a skipped scenario, and a green verification command do not establish behavior acceptance.

## Search removal boundary

- Verify that application and deployed configuration do not require a Meilisearch client, service, process, credentials, endpoint, startup hook, indexing hook, test fixture, fallback, compatibility layer, or old operator path. Inspect deployed state separately from source changes.
- Preserve FoundationDB as the only source for empty-index rebuilding, including creates, edits, and deletes committed during a search outage. Do not read, inspect, export, translate, import, or reuse Meilisearch documents, schemas, settings, synonyms, rankings, results, snapshots, dumps, or volumes as replacement inputs.
- Treat any retained old volume as a separately authorized deletion. Its presence must not configure or start a service. Do not rerun a completed historical removal outage to validate a correction.
- While public search is disabled, require every ordinary, exact-reference, exact-title, filtered, malformed, and omitted-input call to return exactly `Search is temporarily unavailable.` without engine details or an availability estimate. Require one real scenario for every registered non-search MCP tool and an exact registry-to-scenario match. Source writes to FoundationDB and SQL, non-search QA and soak scenarios, and those tools must work without a search service. Activate ranked search only after rebuilding and acceptance.

## Opaque metadata

- Load only required metadata and authentication. Omit product seeds. Create unfamiliar node types, property types, property identifiers, and hierarchy definitions through public operations. Replace all identifiers and require identical declared behavior, coverage, relative rank, and type filtering.
- Store definitions without declarations when their types supply defaults. Verify readable scalars, option labels, and default exclusions, including node references. Explicit inclusion and exclusion override defaults. Search must omit an explicitly excluded value beside an included value in the same fixture. Reject definitions without either a declaration or a default. Property names and `Indexed` must not choose inclusion.
- Require explicit declarations in built-in seeds and QA data for reproducible fixtures. Test included, excluded, absent, scalar, structured, and labeled values. Require name-only nodes to remain searchable.
- Dry-run the expiring projection backfill against a complete reviewed manifest. Require bounded output and unchanged source state. Reject missing, duplicate, unknown, cross-organization, malformed, and conflicting entries. Execute the exact manifest twice and require an unchanged second run. Test concurrent explicit changes and partial-failure recovery. Verify that initial filling leaves ordinary search work unchanged.
- Require readiness before provisioning, rebuilding, and verification. Each command must refuse invalid declarations or definitions without declarations or defaults. Verify readiness separately in QA and production before rebuilding.
- Add a type after startup and search it without restarting or changing application code. Change a projection against the same physical index and alias. Require new semantic fields only for affected pages, byte-identical fields for unaffected pages, and retirement of obsolete affected IDs.
- Put an invalid value, an undeclared property, and an inapplicable definition beside valid content. Require searchable names and valid text. Omit invalid values from indexed text and preserve them in source storage. Verification must warn with node, property, revision, projection, and reason without failing or excluding the node. Repair through the approved boundary, verify the repair, and require durable refresh to clear warnings. Deletion must clear warnings.
- Change renderer semantics without changing stored definitions. Require old cursors to fail, pending work to resume under the new projection, all affected nodes to refresh, and explicit exclusions to remain intact. Stop FoundationDB during metadata refresh and require an explicit error. Concurrent type changes and requests must use complete metadata epochs. Verify that a deleted type disappears from the generated tools. Many opaque properties must preserve the fixed engine mapping.

## Semantic relevance

Use one fixed corpus with at least 150 plausible distractors. Repeat every query three times and after reindexing. Every target must appear within the first 25 distinct nodes without query-specific branches or maintained synonyms.

Each query must retrieve the corresponding text.

| Query | Relevant text |
| --- | --- |
| `db` | Database failover |
| `signin` | Authentication failure |
| `lag` | Slow request processing |
| `invoice` | Billing reconciliation |
| `crash` | Application terminated unexpectedly |
| `remove user` | Delete account |

- Require a lexical-only control to miss at least one non-overlapping pair that the combined query retrieves. Save one query inference and prove byte-identical opaque `query_tokens` on every continuation and replay. A high-level semantic query can replace saved tokens only after it passes every relevance case and continuation latency threshold without repeated inference.
- Preserve the analyzer miss and repeated-inference comparison that justify saved tokens. Capture actual indexed text, model and tokenizer identities, generated sparse fields, query weights, structured filters, lexical boosts, and rank traces for any failure. Preserve the production wording and expected TACK-578 content as a public regression with plausible distractors. Resolve any ticket-to-corpus count mismatch before claiming complete coverage.
- Prepare separate opaque cohorts with 162 semantic nodes, 31 continuation nodes, and one final-page node. The 31 eligible continuation nodes include one node with repeated matching text across multiple reader pages. Traversing the cohort takes at least two responses even with 25 nodes per page. Use the actual stored IDs and expected case IDs. A fixture manifest establishes preparation only.

## Complete page processing

- Use the real reader with a small byte bound. Require indexing before the final read and continuation until explicit completion. Change page counts between reads without changing configuration. Reject changed, missing, or corrupt revisions before combining pages.
- Put targets at the beginning, middle, page boundary, and final page, with a name and value spanning many pages. Require the final-page semantic target within the first 25 distinct nodes.
- Inspect every indexed page's node, revision, projection, and ordinal. Require complete `page_text` and native `page_text_semantic_info.chunks.embedding` output for nonempty pages. Inspect generated chunks for valid Unicode, bounded forward progress, final-character coverage, and one finite sparse result per generated input. Whitespace-only chunks may contain an empty embedding map. The map must still exist.
- Repeat with emoji, combining marks, non-Latin text, Markdown, long URLs, uninterrupted strings, punctuation, whitespace, a valid 4,096-byte page, a newline-only page, active empty text, missing text, retirement records, and unknown fields. Reject missing required text and unknown mapped fields. Accept valid empty text without inference.
- Pin native chunk coverage to 160 characters, zero semantic overlap, and unlimited chunks. Repeat proof after a model, semantic mapping, or bound change. Do not reproduce OpenSearch tokenizer logic.
- Before removing storage limits, test 128 KiB, 1 MiB, 8 MiB, over 100 MB, and nodes larger than worker memory while keeping page and work bounds fixed.

## Authorization and input validation

- Create matching nodes in two organizations and sibling scopes. Require resolved membership, entry-point, scope, and optional-type isolation. Preserve valid nested nodes and separate project scope. Exclude nodes when authoritative permission cannot be established.
- Capture structured access, type, and retirement filters. Quotes and JSON-like input must not alter their meaning. Empty and oversized queries must fail before inference, and accepted input must receive complete processing.
- Corrupt indexed keys and require current FoundationDB checks to withhold forbidden nodes, including UUID-like queries, stale cursors, continuation, and replay. Missing models, invalid mappings, unavailable engines, deleted points in time, and failed authoritative reads must return explicit errors.

## Permission expansion

- Require one policy boundary for resource and caller keys, with only `access.versions`, `access.keys`, and `access.generation` in the engine mapping. Reject a policy that requires another permission field. Replace permission node and relationship identifiers without changing results. Search must not interpret permission types, roles, groups, organization IDs, or scope IDs in a key.
- Change principal membership and require new caller keys without document writes. Established snapshots may remain open, but final checks must use current permission state. Search and replay during pending revoked-permission work must not disclose forbidden nodes.
- Change direct and inherited resource grants. Update only `search_generation` and `access` on every current page. Preserve IDs, text, chunks, and weights byte for byte. Start with generation 1 and update to generation 2. Retry generation 1 and require `ErrObsoleteWrite`. Retry generation 2 and require unchanged content. Undeploy the document model and require success without content reads or inference.
- Pause an old content write across a new access update and an old access write across new content. Reject both stale operations. Require the newest generation, text, and access to survive. Test a page change after the content precondition read and an idempotent retry of the current generation.
- Begin one authority's candidate while the active policy serves requests. New writes must include both versions. Interrupt and resume every scan and verification phase. Change a grant during verification and repeat the affected checks before activation. Transition another authority independently. Keep existing sessions usable and remove old keys after their authority-specific sessions finish.
- Require unchanged physical index, alias, text, chunks, and weights throughout policy transitions. Failure before activation must preserve the active version. Rollback before retirement must reactivate the previous policy without document recovery. After retirement begins, require another ordinary transition.
- Before shipping a policy, use a corpus dominated by forbidden matches and prove that the engine filters them before ranking. Post-search filtering alone fails acceptance. Corrupt indexed keys separately to prove the final source check.

## Distinct results and continuation

- Create 1,501 matching nodes and 36,000 matching pages for one node across three primary shards. Traverse batches of at most 100 and require every eligible node exactly once. End only after an empty raw batch. Preserve score, node ID, and `_shard_doc` sort values under one point in time. Equal scores and IDs must not skip pages.
- Profile sparse `FeatureQuery` operations over `rank_features`. Reject dense scripts, nearest-neighbor `k`, hybrid windows, collapse, and total-result caps.
- Open a snapshot before page creates, edits, and deletes. Require stable established traversal and current results in a new session, subject to current deletion and permission checks before return.
- Put deleted and unauthorized candidates before valid ones. Continue within four batches. Trigger bytes before 25 nodes and preserve the unconsumed candidate. Four batches may use at most four summary operations. Replay must use that same bounded summary path.
- Force four duplicate-only batches. Require an empty public page with continuation and later remaining nodes. Retry lost responses, concurrent calls, process restart, and process replacement. Require committed-page replay, bounded session writes and memory, exact distinct results, and cleanup.
- Verify the two-minute inactivity deadline, renewed point-in-time keep-alive, expired-cursor snapshot deletion, and two-hour absolute deadline under the accepted deployment settings. Neither replay nor activity may extend the absolute deadline.

## Durable work and state lifecycle

- Stop OpenSearch during creates, edits, deletes, metadata changes, and subtree moves. Require committed source writes, explicit search outage, pending durable work, and convergence after restart without another edit or rebuild. Allow five minutes after restart for the engine and model to become ready. From readiness, the public query must return the node created through MCP during the outage within ten seconds.
- Interrupt before and after page checkpoints, refresh, retirement, and partial bulk failure. Resume saved progress and preserve failed pages. Abort a source mutation and verify that neither the mutation nor its search work commits. Pause an old writer across a newer edit or deletion. Old text must not reappear.
- Rebuild with a parentless node. Require completion, search exclusion, and a reason in verification without verification failure. Add a valid parent and require normal indexing and exclusion removal. Engine failures must not exclude nodes or count toward the source-failure attempt limit.
- Repeatedly fail FoundationDB reads for rebuild, cleanup, deleted-node, rescan, and rollout items. Continue retries. Beyond the attempt limit, verification must fail and report kind, ID, attempts, and last error. The worker must log that record once. Completion must clear the count.
- Use a node larger than one slice. Admit at most 32 pages, 5 MiB, or two seconds of new operations. Delay one request beyond two seconds. Require the worker to stop admitting operations, cancel the request at ten seconds, and checkpoint before another claim. Require progress for other live nodes. Cleanup and access work must yield after 100 IDs.
- Run live mutations, access work, cleanup, metadata rescans, rollouts, and rebuilding together. Record page reads, encoded bytes, slice duration, and peak memory. Measure oldest work age for each class and require fair progress. Increase workers under a fixed workload and require improvement without format changes.
- Count FoundationDB search records after convergence and session expiry, then repeat many edits. Remove completed work, obsolete generations, issued IDs, replay records, and obsolete replacement state. Require state to remain independent of edit history.

## Index replacement lifecycle

- Rebuild during creates, edits, deletes, metadata changes, subtree moves, grants, and a candidate-policy transition. Fail scanning, inference, target catch-up, exact validation, and alias switching separately. Require a correct serving alias and resumable recovery. Verify that concurrent writes update the serving and replacement indexes.
- Change text projection without replacement. Require the same physical index and alias, affected-page inference only, unchanged unaffected fields, and obsolete-ID retirement. Transition access during replacement without starting another replacement. Require active and candidate keys on the target before switching.
- Reserve routing shards divisible by all approved split targets. Reject lower or nonmultiplicative primary counts before blocking writes. Keep the source readable behind the alias while engine writes pause. FoundationDB must commit source mutations and retain the pending search work.
- Split from one to two, four, then eight primaries with the document model undeployed. Require green targets, unchanged mappings, documents, generated chunks, weights, saved raw-sparse results, and absence of a FoundationDB node scan. Redeploy and rerun relevance and continuation. Combined lexical scores need not match because shard-local statistics can change.
- Fail write blocking, split creation, catch-up, validation, and alias switching separately. Restore source writes, preserve the old alias, remove failed targets, and resume durable work. Reconcile uncertain external outcomes from actual state.
- Attempt concurrent replacements and require exactly one. Permit at most one serving, one replacement, and one retiring index. Trigger each retired-page, retirement-age, and index-byte threshold and require full rebuilding. Automatic index creation must remain disabled. Exhaust reserved disk and require pending engine work while source writes remain durable.
- Keep a session on the old index while new sessions use the replacement. After the two-hour absolute deadline, bounded cleanup must confirm that the old index has no active sessions. Before deleting it, block writes, revoke write permissions, and disable automatic recreation. Delete the old index through the typed API. Confirm its deletion and cleanup of session and retirement records. Restore a real FoundationDB backup into a disposable environment, create a new restore epoch and empty index, reject restored cursors, and verify current, deleted, relevant, and final-page content.

## Cluster and capacity

- Verify the actual initial QA and production topology against reviewed configuration. Require one combined-role guest each, the OpenSearch 3.8.0, verified REST and transport TLS, IPv6-only access, least-privilege application credentials, zero replicas, QA single-node discovery (`discovery.type: single-node`), and normal production discovery. Configuration alone does not prove those live facts.
- Require at least 8 GiB per model guest, two logical CPUs, 40 GiB fast storage, and a 3 GiB JVM heap under the accepted initial topology. Record model bundle size, reported inference memory, JVM heap, process memory, filesystem use, peak ingest and host memory, and latency. The earlier 4 GiB run tripped the model memory circuit breaker. The 8 GiB run completed and used about 3.4 GiB afterward. Peak workload memory still requires measurement.
- Use one HTTPS endpoint per environment on its hypervisor guest segment. Require the official observer to record only that endpoint. Verify its certificate, backend certificate checks, authenticated readiness, caller restrictions, and one initial backend. Before application cutover, during a fixed number of production queries, proxy records must show the healthy backend accepting requests.
- Stop each search guest during source writes. Require committed FoundationDB writes, explicit search outage, and pending work. After restart, require authenticated readiness and a searchable backlog. Before member-stop tests and after each restart, verify every eligible predictor and matching cached worker and target identities. Shard health alone is insufficient. Preserve the first public error even if later requests succeed.
- Require ML-only inference placement and least-load dispatch. Deploy the model without `node_ids`, require `DEPLOYED` on eligible members after provisioning and restart, and preserve native automatic redeployment. Verify the optional bounded repair gate separately. While repair and public search are enabled, test a model in `PARTIALLY_DEPLOYED` or `DEPLOY_FAILED` without a running deploy task for 30 seconds. Require one process to claim the repair and at most three attempts per stuck episode. Require disabled public search to prevent repair requests.
- Before production scale-out, join members to the existing cluster without another initial bootstrap. Add healthy proxy backends and verify distribution. Set one replica only after at least two data nodes join, wait for green, record replicas with the physical generation, and preserve sparse weights. Split only along reserved routing shards when measured load requires it. With at least three members and one replica, stop each member independently and require endpoint, primaries, inference, search, and indexing availability.
- Alternate a complete QA session between two actual Tack processes, including replay, revocation, replacement, and cleanup without sticky routing. Verify stable hash buckets and bounded scans. A fixed workload must not serialize on one global counter, lease, queue, or key range. Add Tack processes and FoundationDB capacity independently under fixed request and worker workloads and require improvement without format changes.
- Declare corpus size, page distribution, query mix, concurrency, mutation rate, ingestion bursts, rebuild activity, duration, and documented product thresholds before capacity runs. Measure p50, p95, p99, errors, completed throughput, freshness, oldest work age, CPU, peak memory, and disk. Record a missing product threshold explicitly. Offered rates do not establish thresholds.
- Establish a search-only baseline with `ops qa datagen search-load` at offered rates of 1000, 3000, and 5000 requests per minute using distinct first-page queries. Count offered, sent, completed, dropped, and failed requests separately from committed writes. Classify errors and report completed requests per minute and latency percentiles.
- Repeat those rates through real public calls during creates, edits, deletes, permissions, bursts, one rebuild, an isolated outage, and catch-up. Alternate a continuation between two Tack processes during load. Search the same workload's content with unique revision markers and measure freshness from commit to the first returned marker.
- Run bulk import with ordinary edits and sustained queries. Continue after import until the oldest pending work completes. Include lexical and semantic variation, small and large documents, several tenants, and index maintenance. Search and replay while deletion or revoked-permission work remains pending. Fail on any disclosure.
- Compare mixed-workload search latency, errors, throughput, committed writes per minute, freshness, work age, CPU, memory, and disk with the search-only baseline at the same offered rate. Measure both the search guest and hypervisor. Reuse the process-test session and update machinery for reads of 140 unchanged nodes and updates to separate nodes, but do not derive search-capacity claims from `TestSearchActualOSProcessThroughput` or ordinary `ops qa datagen soak`.
- Keep at least 6.26 GiB available on `suburban` during the complete QA workload. Read its `/proc/vmstat` `oom_kill` counter and each Tack guest's cgroup `memory.events` `oom_kill` counter. Stop the workload on any increase, sustained full memory pressure, or repeated telemetry-read failure. Send `SIGTERM` to the running search-load or search-mixed command. Repeat the entire workload after an interruption to complete acceptance.
- Keep QA to one combined-role search guest on `suburban`. Do not create temporary ML-only or data-only guests there. Keep the guest enabled only after the complete QA indexing, query, and rebuild workload satisfies the host memory gate. Measure production capacity separately on `vault`. Initial single-node results do not establish failover or increased OpenSearch capacity.
- Measure non-index disk bytes after provisioning and primary-index bytes after rebuilding. Initial disk capacity must satisfy `(non-index bytes + 3 * primary-index bytes) / 0.85` for serving, replacement, and retiring generations without replicas. Recalculate per-node disk before adding replicas. Model download size and one successful query do not establish disk capacity.
